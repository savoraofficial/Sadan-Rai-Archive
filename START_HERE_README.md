# SADAN RAI ARCHIVES

**Personal research archive | Nepal | Working edition**

## Start here
This archive preserves research materials, field documentation, source references, and the supporting website/application project. It is a personal research archive; it is not represented as an institutionally accredited archive.

### Where to look
- `RESEARCH_LIBRARY/00_MASTER_INDEX/` — indexes, registers, and archive-wide documentation.
- `RESEARCH_LIBRARY/01_KIRAT_KIRANTI/` — Kirat/Kiranti-related research. Keep interpretations linked to their sources and distinguish evidence from hypothesis.
- `RESEARCH_LIBRARY/03_NEPAL_CIVILIZATIONS_AND_HISTORICAL_TRADITIONS/` — broader historical and civilizational context.
- `RESEARCH_LIBRARY/04_SITE_SPECIFIC_HERITAGE/` — research grouped by a specific site. The Bhringeshwor field record is in this section.
- `RESEARCH_LIBRARY/10_EVIDENCE_ANALYSIS/` and `RESEARCH_LIBRARY/10_EVIDENCE_ATTACHMENTS/` — analysis and associated evidence, following the existing project structure.
- `RESEARCH_LIBRARY/11_RIGHTS_AND_PERMISSIONS/` — rights and permission records.
- `src/`, `public/`, `package.json`, and related project files — existing application/site source. Do not rename or move these without checking code paths and build configuration.

## How to read a record
1. Begin with its `README.md` or field report.
2. Check the photo/evidence register for the unique record ID and file name.
3. Open the source register and read the original publication where possible.
4. Treat observations, published claims, interpretations, and unverified hypotheses as different categories.
5. Check the verification status before repeating a conclusion.

## Add future research without reorganizing the archive
Create a new site-specific folder under `RESEARCH_LIBRARY/04_SITE_SPECIFIC_HERITAGE/` using a short, stable, descriptive name. Include a README, field report, evidence register, source register, verification checklist, and rights/permissions notes where relevant. Give every record a unique ID; do not reuse IDs. Preserve original files and add edited/processed derivatives separately.

## Naming and metadata principles
- Use stable, human-readable folder and file names; avoid unnecessary duplicate folders.
- Record title, creator/photographer, date (or `unknown`), place, description, source, rights/permission status, file format, and verification status when known.
- Never guess dates, inscriptions, authorship, or provenance. Mark unknown information explicitly.
- Keep original captures unchanged. Record edits and derivatives separately.
- For long-term preservation, maintain at least two independent backups and periodically verify checksums.

**Naming note:** “Sadan Rai Archives” is the human-facing project name. The existing technical directory `Sadan-Rai-Archive/` is retained to avoid unnecessary path changes to the website/application.
